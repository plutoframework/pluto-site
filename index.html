01 / THE APPROACH

Good conventions.
Room to explore.

Your API needs a clear path.
Not a universe of abstractions.

Pluto brings the considered ergonomics of Laravel to Go API development. A small, opinionated foundation that keeps the interesting part of your application in your hands.

[ A ]

A place for everything.

Paths describe the contract. Handlers translate HTTP. Operations own business logic. Read a project once and know where the next change belongs.

PATH→HANDLER→OPERATION
[ B ]

Nothing up its sleeve.

Explicit constructor wiring and narrow, consumer-owned interfaces. First-party building blocks, considered dependencies, and no magic registration.

New(policy, repository)
[ C ]

Readable is a feature.

Predictable structure and 80-column formatting conventions give humans and coding agents a shared map. Less context gathering. More meaningful work.

Full installation reference ↗
01

Install the CLI.

Make sure your Go binary directory is on PATH.

go install github.com/plutoframework/cli/cmd/pluto@latest
02

Create a place to build.

Choose a new directory and your own module path.

pluto init observatory \
  --module example.com/observatory
cd observatory
go run ./cmd/api
03

Make first contact.

In another terminal, check the public liveness route.

curl http://127.0.0.1:8080/healthz

Then add an endpoint with the CLI example above. Wire authentication and memberships, define role grants, and implement its operation before expecting a successful business response.

What does Pluto generate?+

A Go/Chi application, endpoint models and operations, a TOML project manifest, tests, OpenAPI output, and configurable Docker, mise and fnox development presets. Use --no-docker, --no-mise or --no-fnox on init to omit individual presets.

Where does my code belong?+

Keep HTTP translation in internal/handlers, business logic in internal/operations, and wire explicit dependencies in internal/app. The CLI maintains generated contracts; authored files are created once and preserved. Use pluto fmt and pluto vet with the pinned lint tooling described in the generated README.

Is Pluto ready for my production API?+

Pluto is an early preview. APIs and scaffolding are evolving; review the source and generated code for your use case. PostgreSQL migrations are explicit, tenancy is optional, and identity, resource authorization and deployment policy remain application responsibilities. No independent security audit or production-readiness claim is made.
